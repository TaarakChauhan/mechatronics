Module 5 — Embedded brains

Microprocessors & MCUs

The “brain” of many mechatronic products is a programmable digital computer on a chip. Distinguishing microprocessors (MPU) from microcontrollers (MCU) clarifies architecture choices.

MPU vs MCU

An MPU is a CPU that typically relies on external memory and peripherals (think application processors). An MCU integrates CPU, flash/RAM, timers, ADC, UART, and GPIO on one die — ideal for embedded control. System-on-chips blur lines further with Linux-capable cores beside real-time MCUs.

Memory and I/O

Flash stores programmes; SRAM holds variables; EEPROM/FRAM may hold calibration. I/O includes GPIO, PWM, ADC/DAC, and communications. Interrupts and DMA keep hard real-time responses feasible without busy-waiting everything.

Programming levels

From machine code and assembly, through C/C++, to model-generated code and higher-level scripting on SBCs. Closer to the metal means tighter timing control; higher levels mean faster feature development — pick based on safety and deadlines.

Key idea Embedded success is less about FLOPS and more about deterministic I/O, power, and surviving the electrical environment.

Worked example — interrupt latency budget

A wheel-speed edge must be timestamped within 20 µs. If interrupt entry takes 2 µs, ISR work 5 µs, and worst-case higher-priority interference 8 µs, margin remains 5 µs — acceptable. Add USB stack jitter without priority design and the budget collapses.

Then vs now 8-bit 8051-class parts taught a generation. Today mixed Cortex-M, RISC-V, and Linux SBCs coexist; safety cores and lockstep CPUs appear in automotive and industrial drives.

Key terms

MCU
Microcontroller with integrated memory/peripherals.
ISR
Interrupt service routine.
DMA
Direct memory access — data movement without CPU copying each byte.

Memory maps, boot, and safety cores

Embedded systems fail at boot as often as in steady run: clock trees, brown-out resets, and misconfigured pins. A robust design defines safe defaults on reset (outputs de-energised) before software finishes initialising. Watchdogs should be hardware-backed.

Automotive and industrial MCUs may include lockstep cores or separate safety islands. Application code on a rich core coexists with a simpler certified kernel monitoring timeouts and I/O plausibility — architecture you will meet again in safety PLCs.

Peripheral priorities for mechatronics

Prefer MCUs with enough independent timers for PWM and input capture, ADC with DMA, and hardware CRC for communications. “Faster CPU” rarely fixes missing timer blocks.

Power architecture: brown-out detection thresholds must sit above the voltage where ADC references and flash writes become unreliable. Sequence enables so drivers stay off until configurations complete.

Bootloaders enable field updates — and enable bricking if power fails mid-write. Dual-bank flash or A/B images are worth the pins for products that update.

Security: debug ports left open on production boards are an attack path. Plan lifecycle disablement.

Extended studio notes — 05 microprocessors

In professional mechatronics work, the ideas in this lesson show up less as isolated definitions and more as constraints that fight each other. Deterministic peripherals beat raw MHz for most control products. When you write requirements, force numbers onto those constraints: sample rates, newton-metres, degrees Celsius, milliseconds of latency, millimetres of error. Vague adjectives hide trade-offs until tooling steel is already ordered.

A useful studio habit is to keep a living “assumption list” beside your block diagram. Typical assumptions include linearity, constant temperature, perfect sampling clocks, infinite actuator authority, and noise-free sensors. Assuming reset leaves outputs safe without hardware defaults risks glitch pulses. Crossing out an assumption should trigger either a model upgrade, a hardware change, or an explicit residual risk acceptance signed by someone accountable.

Commissioning is where theory meets cable trays. Expect ground loops, mis-labelled I/O, incorrect engineering-unit scales, and mechanical binding that looks like a “software bug.” DMA overruns silently drop samples; counters and assertions should catch them. Bring an oscilloscope or drive trace tool early; bring a torque wrench and alignment dial indicator just as early. The mechatronic engineer who only debugs in an IDE will misclassify half of field faults.

Documentation is part of the control system. Record firmware hashes, gain sets, mechanical revisions, and network topologies together. Future failure analysis needs that bundle. Security of debug ports is part of embedded architecture in 2026. If your organisation treats documents as after-the-fact paperwork, expect to rediscover tuning constants from scratch after every staff rotation.

Finally, connect this lesson forward and backward in the course. Foundations without modern networks leave you unable to ship connected machines; modern buzzwords without foundations leave you unable to stabilise a simple loop. Edge AI MCUs still need this I/O discipline underneath the model. Use the quizzes not as memorisation theatre but as prompts to redraw the diagrams from memory on paper — that retrieval practice builds the intuition you will need on a noisy factory floor.

Additional worked scenario

ISR budget: ADC end ISR 3 µs, encoder edge 2 µs, worst nested 8 µs, control task reservation 50 µs at 10 kHz (100 µs period). If ISRs consume 20 µs average, CPU loading from interrupts alone is 20% — leave margin for communications stacks.
