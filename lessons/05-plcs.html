Module 5 — Embedded brains

Programmable logic controllers

Programmable logic controllers industrialise embedded control: modular I/O, watchdogs, retained memory, and programming languages standardised in IEC 61131-3.

Scan cycle

Read inputs → execute programme → write outputs → housekeeping. Scan time must fit the process; overly long scans make logic feel laggy and can miss short pulses without pulse catch hardware.

Ladder, latches, timers, counters

Ladder logic visually mimics relay rungs. A seal-in (latch) keeps a coil energised after the start contact opens until a stop contact breaks the seal. Timers (TON/TOF) and counters (CTU/CTD) implement delays and batch counts. Analogue I/O brings scaled engineering units into the same programme for PID blocks.

Figure: Conceptual start/stop with seal-in contact around Start.

Worked example — original latch narrative

Press Start: Start contact true, Stop closed, Run coil energises. Seal-in contact parallel to Start closes, so releasing Start keeps Run true. Press Stop (normally-closed opens): rung de-energises, seal breaks. This pattern appears in conveyors and pump starters worldwide.

Then vs now Ladder-only thinking expands to structured text, OOP function blocks, safety PLCs with diverse languages, and soft-PLCs on industrial PCs (Module 8).

Organisation and analogue scaling

Large PLC programmes need structure: equipment modules, faceplates, and consistent tag naming. Analogue values should live in engineering units after a single scaling step — duplicated scalings drift apart. PID blocks need mode handling (auto/manual), bumpless transfer, and per-loop alarm limits.

Simulation and forcing of I/O help commission safely, but forced points left behind are legendary hazards. Procedures for removing forces belong in the commissioning checklist.

Motion and safety adjacency

Many “PLC projects” actually split: standard PLC for cell logic, motion controller for axes, safety PLC for guards. Define which controller owns which output to avoid dual drives fighting.

Use produced/consumed tags or cyclic bus data with explicit timeouts. A silent network should drop motion to a defined stop, not freeze last velocity.

Analogue alarms need hysteresis to avoid chatter. Discrete debounce belongs in one layer only.

Document the scan time budget after adding diagnostics — diagnostics that double scan time are not free.

Extended studio notes — 05 plcs

In professional mechatronics work, the ideas in this lesson show up less as isolated definitions and more as constraints that fight each other. Readable ladder saves plants during 3 a.m. faults; clever spaghetti costs downtime. When you write requirements, force numbers onto those constraints: sample rates, newton-metres, degrees Celsius, milliseconds of latency, millimetres of error. Vague adjectives hide trade-offs until tooling steel is already ordered.

A useful studio habit is to keep a living “assumption list” beside your block diagram. Typical assumptions include linearity, constant temperature, perfect sampling clocks, infinite actuator authority, and noise-free sensors. Assuming forces will be removed after commissioning is how stuck valves stay forced for years. Crossing out an assumption should trigger either a model upgrade, a hardware change, or an explicit residual risk acceptance signed by someone accountable.

Commissioning is where theory meets cable trays. Expect ground loops, mis-labelled I/O, incorrect engineering-unit scales, and mechanical binding that looks like a “software bug.” Scan overruns make timers lie relative to wall clocks. Bring an oscilloscope or drive trace tool early; bring a torque wrench and alignment dial indicator just as early. The mechatronic engineer who only debugs in an IDE will misclassify half of field faults.

Documentation is part of the control system. Record firmware hashes, gain sets, mechanical revisions, and network topologies together. Future failure analysis needs that bundle. Standardise analogue scaling FBs so each loop does not invent its own maths. If your organisation treats documents as after-the-fact paperwork, expect to rediscover tuning constants from scratch after every staff rotation.

Finally, connect this lesson forward and backward in the course. Foundations without modern networks leave you unable to ship connected machines; modern buzzwords without foundations leave you unable to stabilise a simple loop. Safety PLCs later separate certified logic from this standard layer. Use the quizzes not as memorisation theatre but as prompts to redraw the diagrams from memory on paper — that retrieval practice builds the intuition you will need on a noisy factory floor.

Additional worked scenario

Seal-in motor starter: Start NO, Stop NC, overload NC in series with Run coil; Run contact parallels Start. Overload trip breaks the rung and requires explicit reset — map the same pattern into ST for teams that prefer text, but keep the safety story identical.
